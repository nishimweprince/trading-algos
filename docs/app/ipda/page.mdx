# IPDA

**IPDA** stores the full TradingView **IPDA_Full** Pine indicator and ports only the **IPDA
buy/sell** Supertrend entry into a Python signal service that submits market orders to
[MT5 Trader](/mt5-trader).

Unlike [LuxAlgo](/lux-algo), this service has **no confluence overlays or vetoes** — raw IPDA
▲/▼ labels only.

## What it does

1. **Polls** a market-data endpoint for **1-minute** OHLC candles (one or more `quote`s from
   `SYMBOLS_FILE`, or a single `QUOTE` in legacy mode).
2. **Aggregates** those 1M candles into a configurable **target timeframe**
   (`TARGET_TF_MINUTES`, default **5** minutes), treating the still-forming target candle as a
   live bar.
3. **Recomputes** the IPDA Supertrend entry on every poll, so a signal can fire **mid-candle**.
4. **Gates** on configured trading sessions — executes inside them, notifies outside.
5. **Submits** each executable entry to mt5-trader (`POST /v1/signals`, `X-API-Key`).
6. **Watches** filled trades and notifies once when they reach the break-even MFE trigger.

```
1M candles ──▶ aggregate to 5M ──▶ Supertrend + SMA(13)
                                      │
                            session gate (tokyo / new_york)
                                      │
                     in session ──▶ fire once, lock ──▶ POST /v1/signals (source=ipda)
                     out of session ──▶ notify only (no order)
                                      │
                            MFE break-even advisory (notification)
```

<Callout type="warning">
  Mid-candle signals can repaint before the bar closes. IPDA emits the **first** signal seen for
  a bucket and then **locks** that bucket — at most one entry per target candle. TradingView
  alerts on the same indicator use bar-close frequency, so a label that appears mid-bar and
  disappears before close still produces a live trade here. See
  [Signal Logic](/ipda/signal-logic).
</Callout>
